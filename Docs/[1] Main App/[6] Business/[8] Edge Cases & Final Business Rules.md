# Batch 8 — Edge Cases & Final Rules

**Status:** LOCKED

Deletion, listing inactivity, project lifecycle, ownership transfer, data preservation, worker access (none), snapshots, contact/location, privacy.

**Marketplace correction — LOCKED:** Discover → View information → Contact externally. Inside a PM project: Plan → Assign/reference → Calculate → Record actual expenses. No orders, rentals, checkout, or role-to-role transactions on the platform.

---

# BUSINESS LOGIC — LOCKED

## 1. Project Owner Leaves / Is Suspended

If the project owner leaves or is suspended:

- Project does not get automatically transferred.
- Project becomes inactive/archived.
- Admin can handle it when necessary.

---

## 2. Collaborator Removal

Project Owner can add/remove PM collaborators at any time.

---

## 3. Ownership Transfer

Project Owner can transfer ownership to another PM.

---

## 4. Project Deletion

Project deletion is permanent.

Normal project data can be deleted by the owner according to the project's state.

Important historical records that must legally/business-wise remain preserved are handled separately.

---

## 5. Completed Projects

Completed projects can be reopened:

**Completed → Active**

---

## 6. Archived Projects

Archived projects can be restored when appropriate.

---

## 7. Marketplace Listing Deactivation

Provider listings are not truly destroyed when the provider stops offering them.

They become:

**Active → Inactive**

Therefore, anything already referenced by a project remains intact.

---

## 8. Provider Account Removal

Removing/deactivating a provider account does not destroy its historical information.

Existing company/listing/project references remain preserved.

---

## 9. Worker Account Removal

Same preservation principle applies to workers.

If a worker previously existed in project records, their historical information remains where necessary even if their public account/profile is removed.

---

## 10. Virtual Workers

PMs can create internal workers who have no platform account.

A virtual worker can contain:

- Name
- Profession/role
- Contact information
- Rate
- Start/end date
- Hours/days
- Cost
- Notes

These are internal project records.

---

## 11. Worker Project Access

Workers do **not** get project access.

They cannot access:

- Project information
- Costs
- Expenses
- Materials
- Documents
- Other workers
- Tasks
- Project management features
- Project card/cover (no project visibility at all)

Being assigned to a project is an internal PM/project record, not a user permission relationship.

---

## 12. PM Collaboration

Project Owner and PM collaborators have access to the same complete project data.

There is no complicated feature-level permission system.

---

## 13. Provider Users

Provider/company users invited by the owner have broad/full access to the provider's company data.

---

## 14. Provider Invitations

Only the provider/company owner can invite users.

Invited provider users cannot invite additional users.

---

## 15. Marketplace Price Snapshot

When a PM uses marketplace information in a project calculation, the relevant value is snapshotted.

Example:

Provider:
Steel = $1,000/ton

PM project:
Steel planned price = $1,000/ton

Provider later changes:
Steel = $1,200/ton

The project remains $1,000 until the PM explicitly changes it.

---

## 16. External Contact

Providers can publish contact methods such as:

- Phone
- WhatsApp
- Email
- Website
- Physical address

Users contact the provider directly.

---

## 17. Provider Location

Providers can publish location/business information.

Users can search/filter marketplace providers and offerings by location.

---

## 18. Project Privacy

All PM projects are private by default.

Normal visitors cannot discover, search, or view PM projects.

---

## 19. Data Ownership

Each role fundamentally owns its own data:

- PM → own projects
- Provider → own company and marketplace listings
- Worker → own professional profile
- Admin → platform-wide administration/data

---

## 20. Final Platform Principle — LOCKED

The platform is a civil-engineering information and project-management ecosystem: providers publish resources, workers publish professional profiles, users discover information, and PMs use that information inside their own projects to plan resources, calculate costs, track expenses, and maintain project records. Real-world transactions happen outside the platform.

### The fundamental flow

**Provider**
→ publishes information

**Worker**
→ publishes professional information

**Client / Guest**
→ discovers information → contacts externally

**PM**
→ discovers information → uses it as a reference → plans resources → assigns resources internally → calculates costs → records expenses → manages the project

**Platform**
→ provides the information, project-management tools, calculations, records, search, moderation, and administration.

No marketplace transaction engine.
No order system.
No rental booking system.
No payment processing.
No in-app hiring workflow.
