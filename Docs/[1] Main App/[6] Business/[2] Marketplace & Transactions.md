# BUSINESS LOGIC — LOCKED v2

# Project, Marketplace & User Relationships

## 1. Project Ownership

A Project can be created by:

- Admin
- Project Manager

A Project Manager can own multiple projects.

A Project has a standard lifecycle:

Draft
→ Active
→ Completed
→ Archived

Exact transition rules will be defined later.

---

## 2. Project Collaboration

A project can contain multiple Project Managers.

One PM can be the project owner, while other PMs can collaborate.

PMs can also be workers in the system, but the exact permission model
will be defined separately.

---

## 3. Project Privacy

All PM projects are PRIVATE by default.

Normal visitors cannot discover, search, or view PM projects.

A normal Client/Guest does not automatically become part of a PM's project.

The platform does NOT currently represent a normal "client ↔ project manager"
relationship.

Browsing a provider listing does not attach a client or PM to that provider.

---

## 4. Client / Guest Definition

"Client" means a normal person who may need civil/home services.

Examples:

- Someone who needs carpentry.
- Someone who needs masonry.
- Someone who needs glazing.
- Someone who needs welding/metal fabrication.
- Someone who needs roofing.
- Someone planning construction/renovation of their home.

The Client can use the platform as a marketplace/directory.

They can discover:

- Workers
- Providers
- Materials
- Equipment
- Services
- Prices/information

They can contact the provider directly or visit physically.

They cannot order, rent, check out, or create a commercial relationship
on the platform.

They are NOT necessarily connected to a Project Manager.

---

## 5. Worker Marketplace

Workers maintain public professional profiles.

A profile can contain:

- CV
- Portfolio
- Skills/trades
- Pricing/rates (informational)
- Availability or relevant working information (informational)

Worker profiles are publicly discoverable.

Clients and PMs can search for workers and contact them externally.

A PM can assign/reference a worker **inside their own project** for planning
and cost tracking. That does not hire, rent, reserve, or create a
relationship with the worker on the platform.

Displayed worker rates can include hourly, daily, weekly, monthly, per
project, or other models. These are directory information only.

There is no worker rental/hiring transaction on the platform.

---

## 6. Project Materials

A PM can add theoretical/planned materials to a project.

Example:

Steel
10 tons
Estimated/unit price: X

Cement
500 bags
Estimated/unit price: Y

The project calculates estimated/planned costs from the project inputs.

The "estimated" value is a calculation based on planned inputs,
not a prediction generated by the platform.

A PM may reference a provider listing as a planning aid. That reference
does not create an order, reservation, booking, or provider relationship.

---

## 7. Actual Project Cost

Actual cost is calculated from **manually recorded** project expenses
and actual inputs the PM enters.

Example:

Planned:
Steel = 10 tons × planned price

Actual:
Steel = quantity the PM records as purchased/used × actual price the PM records

The system can therefore compare planned/estimated values against actual
project costs.

The platform does not import actuals from orders (there are no orders).

Exact calculation rules will be defined in Batch 6.

---

## 8. Material Discovery (not procurement)

There is **no** platform procurement path.

### Directory browse

PM or client searches providers/materials, views information, and
contacts the provider outside the platform if they want to deal.

### Internal project record

The PM records planned resources and later records actual expenses
inside the project.

The actual purchase/rental/hiring happens outside the platform.

There is no:

- Order
- Accept/reject
- Checkout
- Payment
- Delivery stepper
- Transaction pipeline between PM ↔ Provider or Client ↔ Provider

---

## 9. Provider Marketplace

Providers are independent companies.

Providers can:

- Create/manage their company profile
- Publish/display materials, equipment, services
- Publish prices and relevant information
- Optionally display quantity/availability as **informational only**

Providers cannot receive or manage orders on the platform.

Multiple providers can display the same kind of material.

Users can therefore compare provider offerings/prices as a directory.

Marketplace items remain directory records owned by the provider.

---

## 10. No Bidding, No Ordering

A PM does NOT publish a requirement for providers to compete.

A PM also does NOT place an order on the platform.

Instead:

PM
→ searches material
→ views providers
→ uses information for planning/reference
→ contacts the provider externally if needed

There is no "request for quotation / bidding" workflow
and no "select provider → purchase" workflow.

---

## 11. Quantity / Availability

Provider quantity/availability is informational only.

The platform does not guarantee stock, reserve stock, or transact against it.

There is no reserved / depleted inventory state driven by platform orders
because there are no platform orders.

---

## 12. Delivery

The platform does not operate delivery logistics and does not track
order/delivery status.

Real-world delivery happens outside the platform.

---

## 13. Payments

The platform does NOT process payments and has no checkout flow.

Payments between:

- PM ↔ Provider
- Client ↔ Provider
- Client ↔ Worker
- Other parties

happen outside the platform.

The platform only records financial values the PM enters for project
planning and actual expenses.

---

## 14. Platform Revenue Direction

No monetization/business model is locked for the current version.

Not in the current business model:

- Provider subscription
- PM subscription
- Paid advertising / featured / sponsored listings
- Verification fees or premium worker monetization

Future possibilities can be discussed later without changing current
directory + project-management logic.

See Batch 7.

---

## 15. Platform Positioning

The platform currently combines two major sides:

### Professional / PM Side

Project Managers use the platform to:

- Manage projects
- Plan materials
- Calculate project costs
- Record actual expenses
- Browse providers for reference
- Browse workers for reference
- Manage internal project resources

### Public Marketplace / Directory Side

Normal people can:

- Discover workers
- Discover providers
- Explore materials, equipment, services
- Compare prices/information
- Contact providers/workers externally

**Core marketplace principle**

Discover → View information → Contact externally.

**Core project principle**

Plan → Assign/reference → Calculate → Record actual expenses.
